# Правила публичного рейтинга

Модуль `backend/app/leaderboard/policy.py` работает только с уже подготовленными **публичными** проекциями анализов. Он не получает SourceCraft-токены, не читает приватные снимки и не пытается определить публичность по URL. HTTP-слой обязан передавать в него только результаты, для которых публичность подтверждена каталогом SourceCraft.

## Отбор снимков из хранилища

`AnalysisStore.list_latest_for_repositories()` принимает только список ID, полученный из public-каталога. Он возвращает последний снимок для каждой пары `repositoryId + methodologyVersion`; более новый v2 не вытесняет последний v1. Затем `project_public_snapshot()` сверяет ID, организацию и slug снимка с записью каталога. Несовпавший снимок исключается. Снимок без числового Score остаётся в отдельном блоке без места.

Так хранилище не сканируется ради выдачи всех отчётов, а private/stale-снимок не получает место из-за одного совпавшего ID. Повреждённый сохранённый формат завершается ошибкой сервиса, а не попадает в выдачу с выдуманными полями.

Каждая проекция содержит `methodologyVersion`. При построении рейтинга вызывающий код обязан выбрать одну версию методики; записи других версий исключаются **до** расчёта мест. Это не позволяет сравнивать Score v1 и Score v2. HTTP-слой позднее должен передавать версию как обязательный query-параметр либо явно выбирать текущую опубликованную версию и возвращать её в ответе.

## Полные и предварительные оценки

В основной рейтинг входят все результаты с числовым Score. Частичная оценка (`isPreliminary = true`) тоже получает место: это не оставляет рейтинг пустым, когда один из источников метрик временно недоступен. Интерфейс обязан явно показать, что оценка предварительная, и вывести её `coverage`; такие строки нельзя выдавать за полные.

`partialTotal` показывает количество предварительных строк внутри основной таблицы. `preliminary` по явному `includePreliminary=true` содержит только готовые отчёты без числового Score; `preliminaryTotal` показывает их число. Отсутствующие данные не становятся нулём.

## Место и сортировка

Место вычисляется до фильтрации по точному числовому Score среди всей переданной публичной выборки **выбранной версии методики**. Равные Score получают общее спортивное место: `1, 2, 2, 4`. Стабильный `repositoryId` упорядочивает строки с одинаковыми Score, но не влияет на их место.

Интерфейс может показать строки по трём порядкам:

| sort | Порядок строк | Что происходит с местом |
| --- | --- | --- |
| `score` | Score по убыванию | остаётся тем же |
| `likes` | лайки по убыванию | остаётся тем же |
| `activity` | последняя активность от новой к старой; неизвестная в конце | остаётся тем же |

Поддержаны фильтры языка и подстроки в `organization/repository`. Они сужают отображение, но не пересчитывают глобальное место репозитория.

Пока каталог SourceCraft не предоставляет подтверждённых likes и last activity в этой проекции, HTTP должен возвращать `null` для этих полей. Для внутренней сортировки неизвестные лайки считаются нулём, но это не скрывается в ответе.

## Следующий этап

Для HTTP `GET /api/v1/leaderboard` осталось соединить public-каталог с уже реализованной проекцией, добавить пагинацию и сформировать ответ фронтенд-контракта. Этот endpoint зависит от отдельного PR каталога SourceCraft, чтобы не дублировать его клиент и правила public-видимости.
