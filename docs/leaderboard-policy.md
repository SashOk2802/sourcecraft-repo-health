# Правила публичного рейтинга

Модуль `backend/app/leaderboard/policy.py` работает только с уже подготовленными **публичными** проекциями анализов. Он не получает SourceCraft-токены, не читает приватные снимки и не пытается определить публичность по URL. Будущий слой хранения обязан передавать в него только явно опубликованные результаты.

## Полные и предварительные оценки

В основной рейтинг входят только результаты с полной оценкой (`isPreliminary = false`). Предварительные результаты не получают места и по умолчанию не отдаются в `preliminaryEntries`; API может включить отдельный блок по явному переключателю интерфейса. `preliminaryTotal` при этом показывает, сколько таких результатов прошло фильтры.

Так мы не сравниваем Score с разным покрытием как равнозначные. Отсутствующие данные не становятся нулём, но и не позволяют частичной оценке вытеснить полную из рейтинга.

## Место и сортировка

Место вычисляется до фильтрации и только по точному числовому Score среди всей переданной публичной полной выборки. Равные Score получают общее спортивное место: `1, 2, 2, 4`. Стабильный `repositoryId` упорядочивает строки с одинаковыми Score, но не влияет на их место.

Интерфейс может показать строки по трём порядкам:

| sort | Порядок строк | Что происходит с местом |
| --- | --- | --- |
| `score` | Score по убыванию | остаётся тем же |
| `likes` | лайки по убыванию | остаётся тем же |
| `activity` | последняя активность от новой к старой; неизвестная в конце | остаётся тем же |

Поддержаны фильтры языка и подстроки в `organization/repository`. Они сужают отображение, но не пересчитывают глобальное место репозитория.

## Следующий этап

Для HTTP `GET /api/v1/leaderboard` ещё нужны PostgreSQL-проекция `leaderboard_entries`, подтверждённый признак публичности от SourceCraft и cursor-пагинация. Их нельзя безопасно заменить чтением всех `analysis_snapshots`: там могут находиться приватные отчёты.
