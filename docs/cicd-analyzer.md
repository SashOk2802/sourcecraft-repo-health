# CI/CD-анализатор

Модуль `backend/app/analyzers/cicd.py` оценивает надёжность CI/CD по готовому
снимку запусков. Он не делает HTTP-запросов и не читает системное время: период
всегда приходит в `AnalysisContext`. Благодаря этому один и тот же снимок
воспроизводимо даёт один и тот же результат.

## Вход

Поставщик получает `RepositoryRef` текущего запуска и возвращает `CicdFacts`.
Факт `CiRunFact` содержит только `slug`, статус, тип события, `created_at` и
необязательную длительность в секундах, вычисленную из подтверждённых
`started_at`/`finished_at`. Полные логи задач, пользователь, текст ошибки и
токены в факты не входят.

| Состояние фактов | Результат |
| --- | --- |
| `runs=None` или source error | `unavailable` без score |
| Неполная страница | `insufficient_sample` без score |
| Пустая история, только ручные, незавершённые или менее 5 итоговых запусков | `insufficient_sample` без score |
| Не менее 5 автоматических запусков с итогом | `measured`, score = доля `success` |

`CicdFacts` не допускает одновременно данные и source error, повторные `slug`
или пометку неполноты без собранных запусков. Неподдерживаемый статус, тип
события или дата без часового пояса также отклоняются до расчёта Score.

`repository_event` — допустимый тип запуска: он входит в `KNOWN_EVENT_TYPES`,
но не в `AUTOMATED_EVENT_TYPES`. Такой факт сохраняется в снимке и не мешает
анализировать остальные запуски, однако пока не влияет на Score, размер
учитываемой выборки и рекомендации. Пять успешных `push` плюс любой один
`repository_event` дают `measured` и Score 100 по пяти учтённым запускам.
История только из `repository_event` даёт `insufficient_sample`, а не `unavailable`.

Для измеренной выборки анализатор дополнительно показывает длительность только
тех автоматических запусков с итогом, у которых SourceCraft отдал обе временные
метки. Выводятся размер временной выборки, медиана и p90 методом nearest-rank:
элемент с индексом `ceil(0.9 * n)` в отсортированном ряду. При наличии минимум
шести таких запусков хронологический ряд делится на равные раннюю и позднюю
половины; при нечётном размере средний запуск исключается. Изменение медиан
показывается в процентах, если ранняя медиана больше нуля. Эти метрики имеют
`normalized_score=null`, поэтому медленный запуск не меняет Score без отдельно
согласованной формулы, а отсутствие timestamps не считается дефектом.

## Подключение SourceCraft

`SourceCraftCicdClient` безопасно получает пагинированные `SourceCraftCiRun`.
Адаптер `collect_cicd_facts` из
`backend/app/integrations/sourcecraft_cicd_facts.py` оставляет только поля,
нужные для анализа: `slug`, статус, тип события, `created_at` и безопасную
числовую длительность, затем создаёт `CicdFacts`. Пустой API `id` не передаётся
в факты и не мешает сбору истории. Интервал с `finished_at < started_at`
отклоняется как несовместимый ответ источника без частичной истории.
Ошибка клиента или несовместимый контракт преобразуются в безопасный
`source_error`, а не в нулевую успешность.

`make_cicd_facts_provider(client)` возвращает поставщик для
`make_analyzer(provider)`. Production dispatcher регистрирует CI/CD через
`sourcecraft_analyzer_provider` и использует сервисный токен SourceCraft для
разрешённых публичных репозиториев. Пользовательский PAT, сохраняемый через
`connect_sourcecraft`, пока не участвует в этой цепочке; приватные репозитории
требуют отдельной проверки прав пользователя перед анализом.

В наблюдённом ответе SourceCraft API поле `id` запуска может быть пустым, но
`slug` содержит номер запуска. Поэтому именно `slug` используется для защиты
от двойного учёта. В измеренной категории отчёт даёт ссылку на историю CI/CD и
до трёх последних неуспешных автоматических запусков из оцениваемого периода.
Ссылки строятся только из безопасных сегментов URL; логи job, текст ошибки и
токен в отчёт не попадают. При `unavailable` и `insufficient_sample` ссылка на
конкретный запуск не создаётся, но есть ссылка на общую страницу запусков.
Она показывает текущее состояние SourceCraft и может отличаться от выборки
за период сохранённого отчёта.

## Проверка

```sh
python -m pytest backend/tests/test_cicd_analyzer.py -q
```

Тесты проверяют формулу, границы периода, отменённые и ручные запуски,
недостаточную выборку, неполную историю, распределение и тренд длительности,
отсутствующие или неверные timestamps, ссылки на выбранные запуски, безопасность
сегментов URL, типы входов, дубли, исключение поставщика и отмену выполнения.
Все данные синтетические либо обезличенные fixtures наблюдавшейся схемы API.
