# Миграции PostgreSQL

Миграция — это версионируемое изменение схемы базы данных. Она позволяет каждому окружению создать одинаковые таблицы и безопасно перейти на новую версию приложения.

## Что уже есть

Alembic хранит применённую версию в таблице `alembic_version`.

Первая миграция создаёт:

- `analysis_snapshots` — неизменяемые JSON- и Markdown-отчёты;
- `analysis_jobs` — состояния запусков анализа.

При первом запуске Docker backend выполняет `alembic upgrade head` до старта FastAPI.

## Команды

После запуска Docker:

~~~powershell
docker compose exec backend alembic current
docker compose exec backend alembic upgrade head
~~~

Для локального Python нужно задать `DATABASE_URL`, установить зависимости и выполнить:

~~~powershell
alembic upgrade head
~~~

## Как добавить изменение схемы

1. Создайте новую ревизию в `backend/migrations/versions/`.
2. В `upgrade()` опишите изменение схемы, а в `downgrade()` — обратное изменение.
3. Примените миграцию к чистой локальной базе и запустите тесты.
4. Добавьте в PR описание влияния на данные и способ проверки.

Автогенерация отключена: в проекте пока нет ORM-моделей SQLAlchemy. SQL миграции пишем явно и ревьюим так же, как прикладной код.

## Существующий Docker volume

Ранние MVP-версии создавали таблицы при старте приложения. Первая миграция сначала проверяет существование таблиц: она не удаляет данные и только фиксирует версию схемы Alembic.
