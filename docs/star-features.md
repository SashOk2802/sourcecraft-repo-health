# Функции со звёздочкой

Раздел 7 ТЗ. Ниже только то, что работает сквозным сценарием на данных SourceCraft; частично сделанное и отсутствующее отмечено отдельно.

## Публичность результата — реализовано

**Публичный API Repo Health.**
- `GET /api/v1/public/repositories/{org}/{repo}/health` отдаёт JSON для сайтов, дашбордов и ботов: Score, покрытие, статусы категорий, дату анализа и версию методики.
- Работает без ключа и сессии.
- Перед каждым ответом репозиторий сверяется с публичным каталогом SourceCraft.
- Закрытый, внутренний, неизвестный и ещё не проанализированный репозитории отвечают одинаковым `404`, поэтому API не раскрывает, что существует.

Руководство и примеры — [public-api.md](public-api.md).

**Quality badge для README.**
- `GET /api/v1/repositories/{org}/{repo}/badge.svg` — SVG-бейдж «repo health | 82», цвет по полосе оценки. Есть вариант по конкретному снимку: `/api/v1/analyses/{id}/badge.svg`.
- Бейдж выдаётся только публичному репозиторию из каталога. Иначе — серый «unknown» без подробностей.
- Бейдж и публичный API кешируются на 5 минут и разрешены для встраивания с других сайтов (CORS). Ошибки не кешируются.
- В отчёте публичного репозитория кнопка «Бейдж и API» даёт готовые фрагменты для README (Markdown, HTML, прямая ссылка на SVG) и адрес публичного API с примером `curl`.

## Защита публичного рейтинга — частично

Сделано на уровне формулы и рейтинга ([leaderboard-policy.md](leaderboard-policy.md), [scoring-methodology.md](scoring-methodology.md)):
- **Место определяет только Score.** Сортировка по лайкам или активности меняет порядок строк, но не места. Лайки в Score не входят вовсе.
- **Активность считается по неделям** (`active_weeks_in_period`, потолок 8 недель). Сотня пустых коммитов за неделю даёт столько же, сколько один. Объём MR и релизов ограничен потолком.
- **Предварительная оценка не получает места**: неполные данные не вытесняют полные.
- **Публичность перепроверяется** при каждом запросе рейтинга: закрытый или удалённый репозиторий из выдачи исчезает.

Отдельного детектора накрутки нет: мы не ищем пустые коммиты по содержимому и аномальные всплески лайков.

## AI-возможности — частично

**AI-рекомендации, подтверждённые фактическими данными.** К каждой детерминированной рекомендации YandexGPT Lite дописывает пошаговый план. Модель получает только факты анализа, а план помечен в отчёте как сгенерированный. Оценка, приоритет и ссылки на факты от AI не зависят. Включается ключом `YANDEX_AI_STUDIO_API_KEY` — [recommendations.md](recommendations.md#ai-план-действий).

AI-summary состояния проекта для менеджера не реализован.

## Рейтинг и сравнение — частично

**История и динамика Score публичного репозитория.**
- `GET /api/v1/public/repositories/{org}/{repo}/history` — до 20 последних сохранённых оценок: дата, Score, покрытие, статус и версия методики. Строится из неизменяемых снимков `analysis_snapshots` без повторного сбора, публичность проверяется по каталогу при каждом запросе.
- В отчёте публичного репозитория — карточка «Динамика Score»: график с порогами 60 и 80, таблица оценок и изменение за период.
- Изменение считается только внутри одной версии методики. Предварительная оценка на графике — полый кружок, оценка без Score — разрыв линии. Пустая история и единственная оценка подписаны как есть.

Сравнения репозиториев и объяснения позиции в рейтинге нет.

## Не реализовано

- **Сравнение репозиториев и объяснение позиции** в рейтинге.
- **Углублённая аналитика:** review-комментарии, bus factor, карта владельцев файлов. Из аналитики задач есть медианное время закрытия (`median_days_to_close`).
- **AI-summary** состояния проекта для менеджера.
