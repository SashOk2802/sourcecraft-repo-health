# Каталог репозиториев SourceCraft

Модуль `backend/app/integrations/sourcecraft_repositories.py` получает доступные
репозитории одной организации через `GET /orgs/{org_slug}/repos`. Он использует
общий `SourceCraftClient`, поэтому Bearer-токен остаётся только в заголовке запроса,
redirect запрещён, а `next_page_token` обрабатывается с защитой от повторения и
лимитом в 100 страниц по 100 элементов.

## Проверяемые поля

Из полного ответа сохраняются только поля, нужные сервису:

- стабильный ID, имя, slug организации и репозитория;
- основная ветка, видимость и признак пустого репозитория;
- язык, число веток и официальный `web_url`;
- минимальный `RepositoryRef` для общего контекста анализа.

Ответ отклоняется целиком, если обязательное поле имеет неверный тип, репозиторий
относится к другой организации, ID или slug повторяется на разных страницах,
счётчик веток не является `uint64` либо `web_url` ведёт не на ожидаемую страницу
`https://sourcecraft.dev/{organization}/{repository}`. Частичный каталог не
выдаётся за полный.

## Защита приватных данных

Имена, ID, slug, основная ветка, язык и URL исключены из `repr` записи каталога.
Тексты ошибок фиксированы и не включают значения полей ответа. Это уменьшает риск
случайно записать метаданные закрытого репозитория в журнал, но сами поля остаются
в памяти и должны передаваться только авторизованному запуску.

## Границы подтверждения

Обезличенный реальный fixture подтверждает форму одной страницы с пустым
`next_page_token`. Переход по двум страницам, пустой каталог, ошибочные поля,
дубликаты и небезопасные URL проверяются локально через `httpx.MockTransport` и
не являются новым живым замером SourceCraft. Реальная многостраничная организация
пока не проверена, поэтому это ограничение остаётся в матрице возможностей.
