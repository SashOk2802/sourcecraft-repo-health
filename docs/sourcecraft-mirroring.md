# Зеркало GitHub в SourceCraft

GitHub — источник истины для Git-истории проекта. Workflow
`.github/workflows/sourcecraft-mirror.yml` переносит в публичный репозиторий
`ereeem13/sourcecraft-repo-health` все ветки и теги вместе с полной историей
коммитов.

Синхронизация запускается:

- после каждого push в `main`;
- каждый час, чтобы подхватывать изменения остальных веток и тегов;
- вручную через `workflow_dispatch`.

Отдельного запуска по событию `push` тега намеренно нет: GitHub выполняет такой
workflow из коммита, на который указывает тег. Без обязательной защиты всех
тегов это позволило бы обойти review основной ветки и обратиться к зеркальному
токену из недоверенного варианта workflow.

При синхронизации удалённые в GitHub ветки и теги удаляются и в SourceCraft, а
расходящаяся Git-история принудительно приводится к состоянию GitHub. Поэтому не
следует делать самостоятельные коммиты в зеркало SourceCraft.

## Настройка доступа

В настройках GitHub-репозитория должен существовать Actions secret
`SOURCECRAFT_PAT`. Он содержит SourceCraft PAT с минимальным правом на запись в
`ereeem13/sourcecraft-repo-health`. Workflow передаёт токен Git через временный
`GIT_ASKPASS` и не добавляет его в URL или Git-конфигурацию.

После замены или отзыва PAT обновите этот secret и запустите workflow вручную.
Успешный запуск дополнительно проверяет, что SHA ветки `main` одинаков в GitHub
и SourceCraft.

## Границы зеркалирования

Зеркалируются только Git-данные: ветки, теги, коммиты и файлы. Pull requests,
issues, комментарии, CI/CD secrets, настройки репозитория и история запусков не
являются Git-данными и остаются независимыми на двух платформах.
