# Browser-защита HTTP API

Backend рассчитан на работу за frontend-прокси: браузер обращается к
относительному пути `/api/...` на том же origin. Поэтому CORS намеренно не
включён: ответ API не содержит `Access-Control-Allow-Origin`, и код с чужого
сайта не может прочитать его через браузер.

Каждый ответ backend, включая обработанный непойманный `500`, получает следующие
заголовки:

| Заголовок | Значение | Назначение |
| --- | --- | --- |
| `X-Content-Type-Options` | `nosniff` | Не позволяет браузеру угадывать MIME-тип ответа. |
| `X-Frame-Options` | `DENY` | Не позволяет встроить ответ в чужой iframe. |
| `Referrer-Policy` | `no-referrer` | Не передаёт URL текущей страницы следующему сайту. |
| `Permissions-Policy` | камера, геолокация и микрофон отключены | API не запрашивает возможности устройства. |
| `Cross-Origin-Resource-Policy` | `same-origin` | Блокирует browser-загрузку ресурса с другого origin в режиме `no-cors`. |

Для JSON и Markdown API-ответов, `/health` и `/openapi.json` дополнительно
выдаётся строгая CSP: `default-src 'none'`. Она не даёт ответу загрузить скрипт,
стиль, форму или другой ресурс. `/docs` и `/redoc` намеренно не получают эту CSP,
иначе перестанет работать интерактивная документация FastAPI; базовые заголовки
на них остаются.

Ответы путей `/api/v1/auth/...` и `/api/v1/me` получают
`Cache-Control: no-store`: браузер и промежуточные кэши не должны сохранять
редиректы входа, сессионные cookie и профиль пользователя.

HSTS здесь намеренно не устанавливается приложением. Его можно включать только
на HTTPS reverse proxy после проверки сертификата и домена: ошибочный HSTS может
надолго лишить пользователей доступа к сайту.
