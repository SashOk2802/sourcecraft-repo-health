# Рабочее пространство frontend

Каталог **frontend/** — отдельное рабочее пространство React + TypeScript + Vite. Его запускает корневой compose.yaml, поэтому frontend-разработчику достаточно команды:

~~~powershell
docker compose up
~~~

## Что делает frontend-разработчик

1. Экран рейтинга репозиториев.
2. Страницу отчёта репозитория: общий Score, шесть категорий и рекомендации.
3. Отображение статусов анализа: выполняется, завершён, нет данных, ошибка.
4. Визуализацию причин, рекомендаций и ссылок на evidence.
5. Экспорт отчёта и обработку ошибок реального API.

Frontend использует согласованный HTTP-контракт: рейтинг, методика, каталог, запуск анализа и отчёты имеют API-клиенты. В чистом Docker-запуске он обращается к backend (`VITE_USE_MOCKS=false`): без настроенного каталога SourceCraft рейтинг и запуск анализа честно вернут `503`. Для офлайн-демо fixtures явно задайте `VITE_USE_MOCKS=true` в локальном `.env` и перезапустите Compose. Для настоящего анализа укажите `SOURCECRAFT_TOKEN` и включите глобальный `SOURCECRAFT_DISCOVER_PUBLIC_REPOSITORIES=true` либо задайте `SOURCECRAFT_PUBLIC_ORGANIZATIONS`.

Вход через Яндекс ID включается настройкой backend: `YANDEX_CLIENT_ID` и `YANDEX_REDIRECT_URI`, а `YANDEX_CLIENT_SECRET` — если его выдал тип OAuth-клиента. Флаг frontend для этого не нужен: интерфейс спрашивает `GET /api/v1/me`. Ответ `401` значит, что вход настроен, и кнопка работает; `503` — OAuth не настроен, и кнопка выключена с пояснением.

## Что frontend не делает

- Не рассчитывает итоговый Score.
- Не решает, считать ли отсутствие данных нулевой оценкой.
- Не обращается к SourceCraft, Git или внешним реестрам.
- Не хранит токены.

Эти правила сохраняют один источник истины: расчёт и объяснение оценки принадлежат backend.

## Как обращаться к API

В коде используйте только относительные пути, например:

~~~ts
fetch("/api/v1/health")
~~~

Vite передаст запрос в backend контейнер. Нельзя прописывать http://localhost:8000 в компонентах: в Docker и в будущем развёртывании это создаст разные конфигурации.

## Структура

~~~text
frontend/
  src/
    App.tsx          корневой компонент и маршрутизация экранов
    main.tsx         точка входа
    styles.css       базовые стили
  vite.config.ts     proxy /api → backend
  package.json       команды dev, check, build
  Dockerfile
~~~

## Правило взаимодействия с backend

Новый или изменённый экран сначала опирается на пример ответа в [контракте API](api-contract.md). Изменение формата ответа согласуют один backend-разработчик и frontend-разработчик до реализации. Pull request с изменением контракта проверяют оба.
