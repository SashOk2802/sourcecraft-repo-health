# Решение по порогам Code health

> Статус: **утверждено** 27.09.2026 владельцем анализа файлов после сверки с
> `docs/technical_specification.pdf` (§3.1, §3.2, §13.2).
> Формула записана в [`docs/scoring-methodology.md`](scoring-methodology.md) §4.3
> и в `backend/app/analyzers/code_health.py`.

Техническое задание не задаёт вес FIXME, ноль при `total_files <= 5` и границу
P1. Команда сама выбирает методику. Жюри смотрит, чтобы слабый сигнал не
определял оценку, а существенная проблема была заметна.

## Плотность: пол знаменателя 10

Знаменатель — `max(total_files, 10)`. Веса прежние: FIXME = 5, TODO = 1.

Один FIXME больше не обнуляет репозиторий из пяти и меньше файлов. На 1 и на
10 файлах score равен 50. На 100 файлах score равен 95. Два FIXME в
репозитории до 10 файлов дают score 0.

Доля файлов с долгом считается по фактическому числу файлов, без пола.

## Приоритет FIXME

`FIXME_CRITICAL_COUNT = 2` остаётся. Один FIXME — рекомендация P2. Два и больше
— P1. Пример высокого приоритета в ТЗ — критические уязвимости AppSec, поэтому
один комментарий не получает P1.
