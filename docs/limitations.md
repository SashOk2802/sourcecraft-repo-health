# Ограничения решения

Что сервис сейчас не умеет или делает с оговорками. Каждое ограничение видно в интерфейсе как статус данных, а не как низкая оценка.

## Данные

- **Security зависит от AppSec SourceCraft.** Собственного сканирования нет (п. 3.1 ТЗ). Если для репозитория нет свежего snapshot AppSec, Security получает «нет данных». Если сводка CLI не подтверждает полноту выборки — «мало данных». Итоговая оценка тогда предварительная. Подробно — [security-analyzer.md](security-analyzer.md).
- **Период — 180 дней.** Activity, Issues и CI/CD смотрят на последние полгода: давняя история на оценку не влияет.
- **Чего не собираем.** Нет review-комментариев, bus factor, времени до первого ответа в задачах и карты владельцев файлов. Из аналитики задач считается медианное время закрытия.
- **Code health узкий.** Категория считает TODO и FIXME в комментариях исходников. Поэтому её вес всего 5% ([scoring-methodology.md § 4.3](scoring-methodology.md)).
- **Лайки и последняя активность** приходят из каталога SourceCraft. Если поля нет, в рейтинге стоит прочерк, а строка при соответствующей сортировке уходит в конец. В Score они не входят.

## Доступ

- **Закрытые и внутренние репозитории** — только по личному токену SourceCraft, который пользователь сам подключает в кабинете: Яндекс ID даёт вход, но не доступ к SourceCraft. Токен хранится зашифрованным и работает только в рамках прав пользователя.
- **Личные отчёты видит только тот, кто запускал анализ.** Готовый снимок системного планировщика доступен всем только пока его репозиторий подтверждён текущим public-каталогом SourceCraft: так строка рейтинга открывает подробный отчёт. Private/internal и личные запуски даже public-репозитория остаются доступны лишь владельцу.

## Исполнение

- **Worker работает внутри процесса backend.** При перезапуске незавершённый личный анализ завершается кодом `worker_interrupted`, и его нужно запустить снова. Плановые анализы повторятся по расписанию сами.
- **Каталог заполняется постепенно.** Планировщик ставит не больше 10 новых заданий в минуту. Глобальный каталог ограничен первыми 25 public-репозиториями в устойчивом порядке SourceCraft, поэтому не становится фоновой выгрузкой всего сервиса. Для точного покрытия организаций используйте `SOURCECRAFT_PUBLIC_ORGANIZATIONS`.
- **Пределы крупных репозиториев** по умолчанию: 50 000 файлов, 750 МБ рабочей копии, 50 000 коммитов, 120 секунд на Git. Они покрывают крупный репозиторий из п. 9.2 ТЗ и настраиваются переменными окружения. За пределом затронутые категории получают статус `error`, остальные считаются ([architecture.md](architecture.md)).
- **Частота SourceCraft API.** При ответе `429` запуск откладывается, а плановый пересчёт повторяется с растущей задержкой.

## Методика

- Веса и пороги экспертные: они обоснованы в [scoring-methodology.md](scoring-methodology.md) и проверены контрольными сценариями, но не обучены на выборке.
- Точный прирост после исправления (`expectedScoreDelta`) считается для Documentation и Code health. Для остальных категорий эффект описан словами ([recommendations.md](recommendations.md)).
- Смена методики меняет версию (`v2`). Рейтинг не сравнивает оценки разных версий.

## AI-план действий

- Текст плана генерирует модель, поэтому он не детерминирован: при повторном анализе тех же данных формулировки могут отличаться. Оценка, приоритеты и факты от него не зависят.
- Корректность плана автоматически не проверяется, поэтому в отчёте он помечен как сгенерированный.
- Если модель недоступна или отвечает дольше тайм-аута, рекомендация остаётся без плана.
- Работает только с ключом Yandex AI Studio. Для закрытых репозиториев их факты уходят в Yandex Cloud ([data-sources.md](data-sources.md#внешние-сервисы-и-ai)).

## Интерфейс

- PDF собирается в браузере (pdfmake): первое скачивание подгружает около 2 МБ библиотеки и шрифта. Markdown отдаёт backend.
- Основной сценарий — настольный браузер. Вёрстка проверена и на телефонах от 320 px.
